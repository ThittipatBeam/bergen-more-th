The judge, in plain termsผู้ตัดสิน อธิบายง่ายๆ

The headline score is not a string match. A Thai-aware LLM reads each model answer next to the documents the pipeline actually pulled, and asks one question: is this answer factually correct given that context? คะแนนหลักไม่ใช่การเทียบข้อความ LLM ที่เข้าใจภาษาไทยอ่านคำตอบของแต่ละโมเดลคู่กับเอกสารที่ระบบดึงมาจริง แล้วถามคำถามเดียว: คำตอบนี้ถูกต้องตามข้อเท็จจริงจากบริบทนั้นหรือไม่

What it creditsอะไรที่ได้คะแนน

A correct answer in different words still earns full credit. So does a different Thai transliteration of the same name — เลดี้ กาก้า and Lady Gaga are the same entity. คำตอบที่ถูกแม้ใช้ถ้อยคำต่างกันก็ยังได้คะแนนเต็ม เช่นเดียวกับการสะกดถ่ายเสียงไทยต่างกันของชื่อเดียวกัน — เลดี้ กาก้า กับ Lady Gaga คือบุคคลเดียวกัน

What it also creditsอะไรที่ได้คะแนนเพิ่ม

A correct refusal. If the retrieved context genuinely lacks the answer, replying ไม่พบข้อมูล is the right call. The judge rewards it; every string metric scores it zero. การปฏิเสธที่ถูกต้อง หากบริบทที่ดึงมาไม่มีคำตอบจริง การตอบ ไม่พบข้อมูล คือสิ่งที่ถูก ผู้ตัดสินให้คะแนน แต่ตัวชี้วัดข้อความทุกตัวให้ศูนย์

Work it yourself — the same answer, two scoringsลองเอง — คำตอบเดียวกัน คะแนนสองแบบ
Q. เพลง The Edge of Glory ร้องโดยใครถาม. เพลง The Edge of Glory ร้องโดยใคร
A. ร้องโดย เลดี้ กาก้า (Lady Gaga)ตอบ. ร้องโดย เลดี้ กาก้า (Lady Gaga)
✓
Judge: correct. Same entity — เลดี้ กาก้า is the Thai transliteration of “Lady Gaga”. The judge cares about the fact, not the exact letters. Score: 1. ผู้ตัดสิน: ถูกต้อง ชื่อเดียวกัน — เลดี้ กาก้า คือการถ่ายเสียงไทยของ “Lady Gaga” ผู้ตัดสินดูข้อเท็จจริง ไม่ใช่ตัวอักษรเป๊ะๆ คะแนน: 1
✗
String match: fail. The reference answer is in English. The Thai transliteration shares no matching tokens, so the overlap is zero — even though the answer is right. Score: 0. เทียบข้อความ: ผิด คำตอบอ้างอิงเป็นภาษาอังกฤษ การถ่ายเสียงไทยไม่มีคำซ้ำกันเลย ความซ้ำเป็นศูนย์ ทั้งที่คำตอบถูก คะแนน: 0
LLMeval_judge_pct = mean(judge_score) × 100 — the share of questions the answer got right, as a percentageสัดส่วนข้อที่ตอบถูก เป็นเปอร์เซ็นต์

The metrics, side by sideตัวชี้วัด เทียบกัน

String metrics compare token overlap against a reference. Thai has no spaces, so the fork tokenizes with pythainlp first — these are the _th metrics. They measure the lexical surface, never the fact. ตัวชี้วัดข้อความเทียบคำที่ซ้ำกันกับคำตอบอ้างอิง ภาษาไทยไม่มีการเว้นวรรค จึงต้องตัดคำด้วย pythainlp ก่อน — นี่คือตัวชี้วัด _th วัดได้แค่ผิวของข้อความ ไม่ใช่ข้อเท็จจริง

  • JudgeHeadline
    Did the model get the fact right against the retrieved context? The only metric that answers the real question.โมเดลตอบถูกเทียบกับบริบทที่ดึงมาหรือไม่ ตัวชี้วัดเดียวที่ตอบคำถามจริง
  • M_thThai Match
    1 if any reference answer string appears anywhere in the response. Generous — a long answer that name-drops the right entity scores full.เป็น 1 ถ้าข้อความคำตอบอ้างอิงข้อใดปรากฏในคำตอบ ใจกว้าง คำตอบยาวที่พาดพิงชื่อถูกก็ได้เต็ม
  • F1_thHarmonic
    Balance of Precision_th and Recall_th over pythainlp tokens. The fairest single string number, still blind to correctness.ถ่วงดุล Precision_th กับ Recall_th บนคำที่ตัดด้วย pythainlp เลขข้อความตัวเดียวที่ยุติธรรมที่สุด แต่ยังมองไม่เห็นความถูกต้อง
  • Recall_thCoverage
    How much of the reference the answer covers.คำตอบครอบคลุมคำในอ้างอิงมากแค่ไหน
  • Precision_thEconomy
    How much of the answer is actually on-reference. The gap metric below shows why it sits lowest.คำตอบมีส่วนที่ตรงอ้างอิงมากแค่ไหน ตัวชี้วัดช่องว่างด้านล่างอธิบายว่าทำไมตัวนี้ต่ำสุด

Why the gap matters hereทำไมช่องว่างจึงสำคัญ

On the measured sheet, judge 69.7 against F1_th 13.1 — and Recall_th (32.1) runs far above Precision_th (10.0). That tells you systems pull the right entity but say too much, and the strings punish correct Thai phrasing. That gap is the whole reason this benchmark exists. บนแผ่นวัด ผู้ตัดสิน 69.7 เทียบ F1_th 13.1 และ Recall_th (32.1) สูงกว่า Precision_th (10.0) มาก แสดงว่าระบบดึงชื่อที่ถูกแต่พูดเกิน และตัวชี้วัดข้อความลงโทษการใช้ถ้อยคำไทยที่ถูก ช่องว่างนี้คือเหตุผลทั้งหมดที่เกณฑ์วัดนี้มีอยู่

Reproduce it yourselfทำซ้ำด้วยตัวเอง

One pipeline definition, three commands. It runs through OpenAI-compatible endpoints with cost guardrails, so no local GPU stack is needed. นิยามไปป์ไลน์เดียว สามคำสั่ง รันผ่านเอนด์พอยต์แบบ OpenAI-compatible พร้อมตัวจำกัดค่าใช้จ่าย ไม่ต้องมี GPU ในเครื่อง

Set EMBED_BASE_URL, RERANK_BASE_URL, LLM_BASE_URL and their keys in .env. The model ids in the config are simply whatever your endpoint serves. ตั้งค่า EMBED_BASE_URL, RERANK_BASE_URL, LLM_BASE_URL และคีย์ใน .env ชื่อโมเดลในคอนฟิกคือชื่อที่เอนด์พอยต์ของคุณให้บริการเท่านั้น

# 1 · run the full Thai pipeline
python3 bergen.py dataset=mkqa/mkqa_th.retrieve_th \
  retriever=api-embed-openai-compatible \
  reranker=api-rerank-openai-compatible \
  generator=openai_compatible \
  generator.init_args.model_name=YOUR_MODEL

# 2 · Thai string metrics auto-enable; judge reads on-disk data
python3 evaluate.py --folder experiments/<exp> --split dev --judge

# 3 · print the table
python3 print_results.py --folder experiments/ --format=tiny

New runs land as new rows on the leaderboard — each row states its own embedding and reranker, because changing either makes it a different system. ผลการรันใหม่จะมาเป็นแถวใหม่บนตาราง — แต่ละแถวระบุเอมเบดดิงและตัวจัดอันดับของตัวเอง เพราะเปลี่ยนอย่างใดอย่างหนึ่งก็เป็นระบบคนละตัว
