# ผลทดสอบโมเดล Cohere บน Thai RAG benchmark (Wikipedia V4)

## สรุปสำหรับผู้บริหาร

ฝั่ง retrieval ของ Cohere อยู่ระดับบนสุดของบอร์ด: embed-v5.0-pro กับ rerank-v4.0-pro ทำคะแนนรวม 93.9 สูสีกับโมเดล open-source ที่ดีที่สุด (QWEN3-EMBED-8B ทำได้ 94.1 ซึ่งต่างกันไม่เท่าความคลาดเคลื่อนของการวัด) แต่ฝั่งสร้างคำตอบเป็นคนละเรื่อง คือ Command A คุณภาพคำตอบต่ำกว่าโมเดลตัวนำราว 2 คะแนน และใน harness ของเราใช้เวลาสร้างคำตอบ 500 ข้อนานกว่า 10–15 เท่า ถ้าจะพิจารณา Cohere จึงควรมองที่ embedding กับ reranker ก่อน generator

## วิธีที่ใช้วัด

69 การทดลองบนคลัง Wikipedia ภาษาไทย (ThaiWikiV4) คำถาม 500 ข้อต่อรัน pipeline แต่ละตัวคือ embedding model -> reranker (ไม่บังคับ) -> generator คะแนนรวมน้ำหนัก 80% มาจาก LLM judge (KIMI-K3 อ่านคำตอบแล้วตัดสินว่าถูกหรือผิดตามเฉลย) และ 20% จาก Match TH (เฉลยเต็มคำปรากฏในคำตอบ) มูลตัวเลขทั้งหมดอยู่บน leaderboard ของเรา

ห้าอันดับแรกของ pipeline เมื่อเรียงตามคะแนนรวม:

| คะแนนรวม | Generator | Embedding | Reranker |
| --- | --- | --- | --- |
| 94.1 | DEEPSEEK-V4.1F | QWEN3-EMBED-8B | bge-reranker-v2-m3 |
| 93.9 | DEEPSEEK-V4.1F | embed-v5.0-pro (Cohere) | bge-reranker-v2-m3 |
| 93.9 | DEEPSEEK-V4.1F | bge-m3 | bge-reranker-v2-m3 |
| 93.9 | DEEPSEEK-V4.1F | embed-v5.0-pro (Cohere) | rerank-v4.0-pro (Cohere) |
| 93.4 | DEEPSEEK-V4.1F | QWEN3-EMBED-8B | rerank-v4.0-pro (Cohere) |

## ประเด็นที่พบ

- Embedding ของ Cohere ชนชั้นนำ: อันดับคะแนนสูงสุดที่ embedding แต่ละตัวทำได้คือ QWEN3-EMBED-8B 94.1, embed-v5.0-pro 93.9, bge-m3 93.9, embed-v4.0 91.9, embed-multilingual-v3.0 90.4 ความต่างระหว่าง v5.0-pro กับตัวนำอยู่ในระดับเสียงเบื้องหลังของ judge จึงเทียบเท่ากันทางสถิติ โดยที่ v5.0-pro เป็น API สำเร็จรูป ไม่ต้องจัดการ infra เอง
- Reranker เพิ่มคะแนนทุก pipeline ที่เทียบกันได้ ราว +0.7 ถึง +11.3 คะแนน (โดยเฉลี่ยประมาณ +2.8) ยิ่ง embedding ตัวถูกหรือตัวเบา ยิ่งได้ประโยชน์มาก เช่น embed-multilingual-v3.0 กระโดดจาก 79.2 เป็น 90.4 เมื่อใส่ reranker
- Generator เป็นตัวตัดสินอันดับ: DEEPSEEK-V4.1F ทำสูงสุด 94.1, QWEN3.6-27B 93.0, command-a-03-2025 91.9, command-a-plus-05-2026 90.1, GPTOSS-120B 88.7 โมเดล Command A ของ Cohere อยู่กลางกลุ่ม และรุ่น plus ที่ใหม่กว่ากลับไม่ได้ดีกว่ารุ่นเดิมในชุดทดสอบนี้
- ความเร็วของ Command A ต่ำผิดปกติ: เวลาสร้างคำตอบครบ 500 ข้อ (ค่ามัธยฐาน) คือ command-a-03-2025 141 นาที, command-a-plus-05-2026 92 นาที ขณะที่ DEEPSEEK-V4.1F ไม่ถึง 10 นาทีและ GPTOSS-120B ราว 4 นาที ตัวเลขนี้สะท้อน throughput ของ API ผ่าน harness เรา ไม่ใช่ latency ต่อ request แต่ถ้างานต้องเขียนคำตอบจำนวนมาก ตัวเลขนี้มีผลต่อเวลาที่ใช้จริงโดยตรง
- โมเดลเชิงประหยัดของ Cohere ต้องระวัง: embed-v5.0-fast ทำสูงสุดแค่ 86.6 (ห่าง pro มาก) และ embed-multilingual-light-v3.0 อยู่ที่ 82.5 reranker ช่วยปิดช่องว่างได้บางส่วนแต่ไม่หมด

## แปลผลต่อเรื่อง Cohere

สิ่งที่ทีม Cohere เปิด API มาให้ทดสอบพิสูจน์ได้ชัดในส่วน retrieval: embed เทียบเท่าโมเดลเปิดตัวเก่งสุดโดยไม่ต้องดูแล infra เอง และ reranker ทำคะแนนระดับเดียวกับ bge-reranker-v2-m3 ตัวนำเปิด ถ้าบริษัทมองหา Thai RAG แบบ production จุดที่ Cohere น่าสนใจที่สุดคือแทน open-source ในขั้น search + rerank แล้วปล่อยให้ generator เป็นของที่เราเลือกเอง เพราะสองขั้นแรกนั้นคะแนนตำแหน่งบนสุด ส่วน generator ของ Cohere ในชุดทดสอบนี้ทั้งช้าและทำคะแนนด้อยกว่า จึงยังไม่ควรหาคำตอบไปใช้กับงานจริงก่อนหาข้อมูลละเอียดเรื่องราคาต่อ token และ latency จาก Cohere

## ข้อจำกัดของตัวเลขชุดนี้

วัดจาก dataset เดียว (คำถามสังเคราะห์จาก Wikipedia ไทย 500 ข้อ) ผู้ตัดสินเป็น LLM ไม่ใช่เฉลยที่คนเขียน ความต่างราว 1 คะแนนบนสเกล 100 จึงพูดไม่ได้ว่าฝ่ายหนึ่งเหนืออีกฝ่ายจริง เวลาสร้างขึ้นกับวิธีเรียก API ของ harness เราและอาจต่างจากค่าประกาศของผู้ให้บริการ ตัวเลขทั้งหมดพร้อมให้ดูบน leaderboard เดียวกันทั้งทีมเพื่อแปลผลร่วมกัน

## ขั้นต่อไปที่ควรทำ

1. วัดซ้ำหลายรอบกับ pipeline ที่นำหน้า 3–4 ตัวเพื่อล็อกตัวเลขเมื่อเทียบหัวตาราง ตอนนี้ห่างกันน้อยกว่าความคลาดเคลื่อน
2. ทดสอบกับโดเมนจริงของบริษัทแทนที่จะตัดสินจาก Wikipedia อย่างเดียว ระบบเดียวกันนี้รัน NitiBench+ (เอกสารกฎหมายไทย) ได้แล้วและมีรันแรก 4 ตัว ขยายฝั่งนี้จะเห็นว่า retrieval ของ Cohere รับมือเอกสารกฎหมายได้แค่ไหน
3. ขอตัวเลข latency ต่อ request และราคาต่อล้าน token จาก Cohere โดยตรง โดยเฉพาะฝั่ง generator เพื่อเทียบได้ว่า latency ต่ำในหน้างานของเราด้วยหรือไม่
4. สร้างหน้ากระดาษเปรียบเทียบต้นทุนต่อ 1,000 query ของสามทางเลือก (open-source self-hosted, Cohere แค่ retrieval, Cohere เต็มระบบ) ตัดสินใจจากบรรทัดนี้จะตรงคำถามฝั่ง procurement ของฝ่ายบริหารมากกว่าคะแนน benchmark อย่างเดียว
